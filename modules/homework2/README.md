# Домашнее задание №2 — ПОС

ПОС (Преподавательская Оценка Студентов) — консольное приложение для одного курса.
В нём можно добавлять и просматривать студентов и критерии, выставлять, исправлять и отменять оценки,
считать взвешенный итог и выгружать итоги всех студентов в CSV.

## Запуск

Нужен JDK 17 и Gradle Wrapper из репозитория. При первом запуске Gradle скачает зависимости.
Выполните из корня репозитория:

```bash
# Интерактивное меню
./gradlew :modules:homework2:run --console=plain

# Сквозная демонстрация с выгрузкой
./gradlew :modules:homework2:run --args='--demo' --console=plain

# Сборка, тесты, Checkstyle и проверка покрытия строк от 60%
./gradlew :modules:homework2:build
```

Демонстрация создаёт `modules/homework2/pos-demo.csv`. Для другого пути передайте его после
`--demo`, например `--args='--demo /tmp/pos-demo.csv'`. В Windows используйте `gradlew.bat`.
Из архива в `modules/homework2/build/distributions/` приложение запускается через `bin/homework2`
или `bin/homework2.bat`.

## Работа с приложением

Команда `?` показывает меню, `0` закрывает приложение. Укажите уникальный код и имя студента.
Для критерия введите код, название, положительный максимальный балл и положительный вес.
Регистр кодов значим. Дробные числа можно вводить через точку или запятую.

Для оценки укажите коды студента и критерия, балл и необязательный комментарий.
Повторный ввод для той же пары исправляет оценку. Команда отмены удаляет её.
CSV выгружается в UTF-8, содержит одну строку на студента и показывает процент, количество
выставленных оценок и количество критериев. Укажите путь в существующую папку.
Повторный экспорт по тому же пути заменит файл. Ведомость хранится в памяти до выхода из программы.

Демонстрация добавляет двух студентов и два критерия с весами 40 и 60. Она показывает отказ
при попытке выставить 12 из 10, исправление оценки за проект и отмену оценки у второго студента.
Анна получает **86.00%** (2 из 2 критериев), Илья — **40.00%** (1 из 2). Оба итога попадают в CSV.

## Правило итогового балла

`Итог (%) = 100 × Σ(вес × балл / максимум) / Σ(вес)`

В знаменателе используются веса всех критериев. Поэтому веса могут быть, например, 2 и 3
или 40 и 60. Критерий без оценки даёт нулевой вклад, но отличается от выставленного нуля
в счётчике выполненных оцениваний. Для пустого рубрикатора процент отсутствует,
а в CSV поле остаётся пустым. Итог округляется до двух знаков по правилу HALF_UP.
После любого изменения ведомости следующий запрос рассчитывает процент заново.

## Карта DDD

| Термин | Тип | Ответственность |
| --- | --- | --- |
| Студент | `Student`, Entity | Студент определяется своим кодом, имя служит для отображения |
| Критерий | `Criterion`, Entity | Критерий с уникальным кодом, положительным максимумом и весом |
| Балл | `Score`, Value Object | Неотрицательное число. Например, `3.0` и `3.00` равны |
| Оценка | `Evaluation` | Балл и комментарий по паре студент–критерий |
| Ведомость | `Gradebook`, корень агрегата | Владеет списком студентов, рубрикатором и оценками. Проверяет ссылки и уникальность |
| Итог | `StudentResult` и `ResultCalculator` | Доменный сервис вычисляет результат из текущего рубрикатора и оценок |
| Хранение | `GradebookRepository`, порт | Загружает и сохраняет ведомость |

Студенты, критерии и оценки входят в один агрегат, поскольку для выставления оценки нужны
ссылки на существующего студента и критерий из того же рубрикатора. `Gradebook` разрешает ссылки
по кодам, затем `Evaluation.create` проверяет диапазон баллов до сохранения.
При ошибке прежняя оценка сохраняется. Критерии после создания фиксированы, поэтому изменение
максимума не может сделать выставленные баллы недопустимыми.

## Архитектура Ports and Adapters

`adapter → application → domain`. Адаптер хранения реализует порт `GradebookRepository` из
домена. CSV-адаптер реализует порт `ResultsExporter` из приложения.

- `domain` содержит модель, инварианты и расчёт. Он использует только стандартную библиотеку Java.
- `application` координирует сценарии. Консоль обращается к `PosFacade`.
- `adapter.console` читает команды и отображает данные. `adapter.memory` хранит снимок ведомости.
  `adapter.csv` записывает результаты в файл.
- `config.AppConfig` связывает реализации с портами через Spring DI.
  `Main` поднимает контекст и подключает консоль к фасаду.

Приложение запускается в одном потоке. Адаптер хранения возвращает копию ведомости.
Фасад сохраняет её после успешной доменной операции. Итоги для одного экспорта берутся
из одного снимка ведомости.

## Паттерны GoF

| Группа | Паттерн | Где и зачем |
| --- | --- | --- |
| Порождающий | Factory | `Evaluation.create` — единый вход для создания и исправления оценки. Приватный конструктор оставляет проверку максимума в фабрике |
| Структурный | Facade | `PosFacade` даёт консоли операции предметной области и координирует репозиторий, расчёт и экспорт |
| Поведенческий | Strategy | `ResultCalculator` делегирует формулу стратегии `ScoringStrategy`. Штатная `WeightedScoring` учитывает весь рубрикатор, а тест проверяет подмену формулы |

## Проверки

- `GradebookTest` проверяет дубликаты, существование студента и критерия, границы балла,
  исправление и отмену оценки.
- `ResultCalculatorTest` проверяет формулу, пересчёт при изменениях, отсутствие рубрикатора,
  округление и подмену стратегии.
- `PosIntegrationTest` поднимает реальный Spring-контекст и проверяет демонстрацию,
  интерактивные команды, обработку ошибок и содержимое CSV.

Отчёты лежат в `modules/homework2/build/reports/` в разделах `tests/test`,
`jacoco/test/html` и `checkstyle`.
